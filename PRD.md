# PRD: NET FM Player for AzuraCast

- **Статус:** утверждённая продуктовая основа
- **Версия документа:** 1.1
- **Дата:** 8 августа 2026
- **Автор продукта:** omhotey
- **Бренд:** [VibeService](https://vibeservice.ru/)
- **Лицензия:** GPL-2.0-or-later
- **План распространения:** бесплатный open-source плагин с публикацией в WordPress.org; коммерческая редакция может рассматриваться после стабильного бесплатного релиза

## 1. Резюме продукта

**NET FM Player for AzuraCast** — универсальный WordPress-плагин для публикации интернет-радио на базе AzuraCast и прямых аудиопотоков.

Плагин предоставляет адаптивный аудиоплеер, данные текущего эфира, визуальные темы и единый конструктор представлений. Плеер размещается через shortcode, Gutenberg, Elementor или PHP API. При недоступности AzuraCast API воспроизведение прямого потока должно продолжать работать.

Первая стабильная версия ориентирована на одну публичную станцию. Внутренняя архитектура не должна блокировать последующее добавление нескольких станций, приватных станций, внешнего embed и других расширений.

### 1.1. Текущая контрольная точка

Рабочий baseline от 8 августа 2026 включает:

- одну станцию с primary, secondary и опциональным Auto (HLS) потоками;
- нативное HLS-воспроизведение только в браузерах, которые его поддерживают; при отсутствии поддержки выбирается обычный поток;
- Now Playing polling, предзагрузку `playing_next` artwork и плавную смену metadata/обложки;
- защиту от кратковременной буферизации и ограниченное восстановление потока после устойчивого stalled-состояния;
- завершённую responsive Vinyl-композицию с tonearm, reduced motion и отсутствием горизонтального overflow;
- station label в шапке Vinyl на desktop и mobile;
- скрытое до реализации нескольких станций меню выбора, чтобы не показывать неработающий control;
- shortcode и Elementor controls, синхронизированные с HLS-настройкой.

Metadata API ожидается как корректный UTF-8 JSON. Поля, содержащие символ замены Unicode (`U+FFFD`) после декодирования ответа, не отображаются как название или исполнитель: применяется безопасный fallback. Перекодирование ответов с неверной серверной кодировкой не выполняется на стороне браузера.

## 2. Позиционирование и название

### 2.1. Публичное название

- **Название:** NET FM Player for AzuraCast
- **Рекомендуемый WordPress.org slug:** `net-fm-player`
- **Text domain:** `net-fm-player`
- **Author:** omhotey
- **Author URI:** `https://vibeservice.ru/`

Название подчёркивает независимый бренд и описывает совместимость с AzuraCast, не заявляя официальную принадлежность к проекту AzuraCast.

### 2.2. Технические контракты

Поскольку выбранное название сохраняет NET FM, существующие публичные идентификаторы остаются базовыми контрактами:

| Контракт | Значение |
|---|---|
| Shortcode | `[net_fm_player]` |
| WordPress option | `net_fm_player_options` |
| CSS/JS asset handles | `net-fm-player` |
| Elementor widget name | `net-fm-player` |
| PHP prefix | `Net_Fm_Player_` / `net_fm_player_` |
| CSS namespace | `.nfp` |
| JavaScript API | `window.NetFmPlayer` |
| Storage prefix | `nfp_` |
| Gutenberg block | `net-fm-player/player` |
| REST namespace | `net-fm-player/v1` |

До релиза допускается улучшать структуру атрибутов, но опубликованные контракты после версии 1.0 должны сохранять обратную совместимость.

## 3. Проблема

AzuraCast предоставляет публичные API и базовый embed-плеер, но владельцам WordPress-сайтов не хватает:

- визуально настраиваемых дизайн-тем;
- единого интерфейса настройки без ручной работы с API;
- нативной интеграции с Gutenberg и Elementor;
- устойчивого direct-stream fallback;
- адаптивных layouts, включая sticky и floating;
- сохранённых пресетов плеера;
- диагностических инструментов для API, CORS и потоков;
- согласованного интерфейса на русском и английском языках.

## 4. Цели

### 4.1. Цели версии 1.0

1. Подключить одну публичную станцию AzuraCast по base URL и station shortcode.
2. Автоматически получить сведения о станции и доступных mount points.
3. Воспроизводить эфир даже без доступных метаданных.
4. Предоставить законченные темы Square и Vinyl.
5. Обеспечить layouts Full, Compact, Mini, Sticky и Floating.
6. Предоставить визуальный конструктор с live preview.
7. Интегрироваться с shortcode, Gutenberg, Elementor и PHP-шаблонами.
8. Соответствовать требованиям WordPress.org, безопасности и WCAG 2.2 AA.
9. Работать без обязательных production-зависимостей и build-системы.
10. Поддерживать русский и английский языки.

### 4.2. Метрики успеха

Для первого релиза используются технические и продуктовые показатели без встроенной телеметрии:

- подключение публичной станции без ручного формирования API URL;
- начало воспроизведения не более чем за одно действие пользователя;
- сохранение прямого потока при ошибке metadata API;
- отсутствие JavaScript-ошибок в поддерживаемых браузерах;
- отсутствие PHP warnings/notices в штатных сценариях;
- одинаковый результат renderer в shortcode, Gutenberg и Elementor;
- полная клавиатурная доступность элементов управления;
- отсутствие конфликтов CSS с темой сайта;
- успешная проверка WordPress.org Plugin Check перед публикацией.

## 6. Пользователи и сценарии

### 6.1. Владелец радиостанции

1. Устанавливает и активирует плагин.
2. Открывает мастер подключения.
3. Вводит URL AzuraCast и shortcode станции.
4. Проверяет соединение и найденные потоки.
5. Выбирает тему и layout.
6. Сохраняет пресет.
7. Копирует shortcode или размещает Gutenberg/Elementor-виджет.

### 6.2. WordPress-редактор

- выбирает сохранённый пресет;
- при необходимости задаёт разрешённые локальные overrides;
- видит предварительный просмотр;
- не вводит API URL и поток повторно.

### 6.3. Слушатель

- запускает и приостанавливает эфир;
- регулирует громкость и mute;
- переключает доступное качество;
- видит текущий трек, обложку, статус, слушателей и live DJ;
- использует клавиатуру, медиаклавиши и экран блокировки;
- получает понятное состояние при offline, CORS или сетевой ошибке.

Для версии 1.0 управляется одна станция, но допускается несколько сохранённых пресетов внешнего вида этой станции.

### 7.1. Обзор

- состояние подключения;
- текущий трек;
- основной поток;
- найденные mount points;
- активный пресет;
- быстрые действия;
- предупреждения конфигурации.

### 7.2. Подключение

- AzuraCast base URL;
- station shortcode;
- явный Now Playing API URL как расширенный override;
- основной direct stream;
- резервный direct stream;
- fallback artwork;
- кнопка проверки;
- результат диагностики.

### 7.3. Конструктор

Интерфейс опирается на предоставленный визуальный референс конструктора AzuraCast, но адаптируется к WordPress Admin и бренду VibeService.

Структура desktop-интерфейса:

- слева — настройки;
- справа — код размещения и управление пресетами;
- снизу — live preview;
- на узком экране колонки переходят в последовательный поток.

Верхний блок:

- тип виджета: в 1.0 активен только «Радиоплеер»;
- будущие типы «Играло ранее», «Подкасты», «Расписание» видны только после реализации либо полностью скрыты;
- тема: Square или Vinyl;
- цветовая схема: светлая или тёмная;
- сброс текущего пресета к значениям темы.

Вкладки конструктора:

1. **Оформление**
   - основной, фоновый и текстовый цвета;
   - accent/muted/error цвета;
   - размер обложки;
   - радиус и тень;
   - включение обложки;
   - выбор visualizer;
   - light/dark scheme.

2. **Функциональность**
   - начальная громкость;
   - autoplay с предупреждением об ограничениях браузера;
   - громкость;
   - прогресс трека;
   - выбор потока;
   - слушатели;
   - live DJ;
   - Media Session;
   - поведение reconnect.

3. **Макет**
   - Full, Compact, Mini, Sticky или Floating;
   - ширина с безопасной валидацией CSS size;
   - минимальная высота;
   - позиция sticky/floating;
   - отступы от safe area;
   - поведение на desktop/tablet/mobile.

4. **Расширенное**
   - polling interval в безопасном диапазоне;
   - metadata fallback;
   - custom CSS — не входит в первоначальный MVP без отдельного security review;
   - экспериментальное быстрое восстановление после перехода;
   - отладочная информация для администратора.

Правая панель:

- shortcode;
- PHP snippet;
- кнопка копирования;
- название пресета;
- сохранение;
- список пресетов;
- импорт/экспорт пресетов после стабилизации схемы данных.

Для версии 1.0 панель не генерирует внешний iframe. iframe embed относится к более позднему релизу.

Показывает без раскрытия секретов:

- корректность station shortcode;
- публичность станции;

- HTTPS/mixed content;

## 8. Frontend UX

### 8.1. Темы

#### Square

- квадратная или прямоугольная композиция;
- приоритет обложки и читаемых метаданных;
- подходит для sidebar, карточек и секций страницы;
- поддерживает Full, Compact и Mini.

#### Vinyl

- визуальный образ виниловой пластинки;
- состояние воспроизведения отражается вращением;
- анимации учитывают `prefers-reduced-motion`;
- сохраняется читаемость и доступность на узких экранах.

### 8.2. Цветовая схема

Тема и цветовая схема — разные параметры:

- **тема** задаёт композицию и визуальную концепцию;
- **схема** задаёт light/dark palette;
- администратор выбирает схему вручную;
- автоматическое следование системе не является обязательным для 1.0.

### 8.3. Layouts

- **Full:** полный набор данных и controls.
- **Compact:** сокращённая горизонтальная или вертикальная карточка.
- **Mini:** play, базовые метаданные и минимальные controls.
- **Sticky:** закрепление сверху или снизу контейнера/viewport.
- **Floating:** плавающая карточка в одном из углов с настраиваемыми отступами.

### 8.4. Адаптивность

- mobile-first поведение;
- отсутствие горизонтальной прокрутки;
- touch targets не менее 44×44 CSS px;
- логический порядок чтения сохраняется при перестроении;
- длинные названия не ломают controls;
- sticky/floating учитывает `env(safe-area-inset-*)`;
- CSS изолирован под `.nfp`.

## 9. Функциональные требования

### 9.1. Подключение и конфигурация

- **FR-CON-001:** плагин хранит одну глобальную конфигурацию станции в `net_fm_player_options`.
- **FR-CON-002:** URL очищаются через `esc_url_raw`, текстовые значения — соответствующими WordPress sanitizers.
- **FR-CON-003:** плагин строит `/api/nowplaying/{station}` из base URL и shortcode либо использует явный API URL.
- **FR-CON-004:** direct stream не требует AzuraCast URL.
- **FR-CON-005:** сохранение недействительной настройки не должно создавать произвольный proxy URL.
- **FR-CON-006:** настройки имеют версию схемы для будущих миграций.

### 9.2. Получение данных AzuraCast

- **FR-AZ-001:** Now Playing обновляется polling-запросом с базовым интервалом 15 секунд.
- **FR-AZ-002:** скрытая вкладка не продолжает частый polling.
- **FR-AZ-003:** ошибки используют exponential backoff и не очищают последние корректные данные немедленно.
- **FR-AZ-004:** плеер читает `station`, `now_playing`, `listeners`, `live` и `mounts` только при наличии ожидаемой структуры.
- **FR-AZ-005:** недоступность метаданных не блокирует `<audio>`.
- **FR-AZ-006:** пользовательские API keys не передаются во frontend и не требуются в 1.0.

### 9.3. Потоки и воспроизведение

- **FR-PLY-001:** используются основной и резервный поток.
- **FR-PLY-002:** доступные mount points могут формировать selector качества.
- **FR-PLY-003:** MP3/AAC обычный поток имеет приоритет для совместимости.
- **FR-PLY-004:** HLS является опциональным progressive enhancement: используется только при нативной поддержке браузером, иначе выбирается доступный MP3/AAC поток. Подключение JavaScript HLS fallback не входит в 1.0.
- **FR-PLY-005:** `play()` всегда обрабатывает rejected Promise.
- **FR-PLY-006:** reconnect ограничен, использует backoff и не создаёт бесконечный цикл.
- **FR-PLY-007:** запуск одного экземпляра приостанавливает другие экземпляры NET FM Player на странице.
- **FR-PLY-008:** volume, mute и выбранный поток сохраняются локально.
- **FR-PLY-009:** autoplay выключен по умолчанию и сопровождается пояснением об ограничениях браузера.
- **FR-PLY-010:** Media Session получает title, artist, album и artwork.

### 9.4. Visualizer

- **FR-VIS-001:** режим Auto выбирает реальный анализатор только при совместимом CORS.
- **FR-VIS-002:** при невозможности Web Audio используется декоративная визуализация состояния воспроизведения.
- **FR-VIS-003:** реальный analyser не должен ломать нативное воспроизведение cross-origin потока.
- **FR-VIS-004:** JS-анимации прекращаются при destroy и reduced motion.
- **FR-VIS-005:** Square и Vinyl могут иметь разные visualizer renderers.

### 9.5. Renderer и интеграции

- **FR-INT-001:** shortcode, Gutenberg и Elementor используют один PHP renderer.
- **FR-INT-002:** shortcode `[net_fm_player]` поддерживает глобальные настройки и документированные overrides.
- **FR-INT-003:** неоднозначность `stream_primary`/`stream_primary_url` устраняется до 1.0 с документированным приоритетом.
- **FR-INT-004:** Gutenberg использует dynamic block `net-fm-player/player`.
- **FR-INT-005:** Elementor widget сохраняет имя `net-fm-player`.
- **FR-INT-006:** PHP API возвращает строку и не выводит её без явного вызова интегратора.
- **FR-INT-007:** assets загружаются только на страницах, где нужен плеер, насколько это позволяет способ размещения.
- **FR-INT-008:** повторная инициализация Elementor не создаёт дублированные timers/listeners.

### 9.6. Пресеты

- **FR-PRE-001:** одна станция может иметь несколько сохранённых пресетов плеера.
- **FR-PRE-002:** пресет содержит тему, схему, layout и разрешённые display/behavior options.
- **FR-PRE-003:** секреты и API keys не входят в экспорт.
- **FR-PRE-004:** изменение глобальной станции применяется ко всем пресетам, если в будущем не добавлен явный station binding.
- **FR-PRE-005:** схема пресета имеет версию.

## 10. Непрерывное воспроизведение

### 10.1. Версия 1.0

В обычной многостраничной WordPress-навигации документ и `<audio>` уничтожаются. Поэтому 1.0 предоставляет:

- Sticky/Floating в пределах текущей страницы;
- сохранение пользовательских параметров;
- экспериментальное быстрое восстановление после загрузки следующей страницы, когда это разрешает браузер;
- отсутствие обещания бесшовного перехода.

### 10.2. Будущая версия

Настоящий Continuous Playback требует постоянного player shell и AJAX/History API навигации. Эта функция должна быть опциональной и тестироваться отдельно на совместимых темах. Нельзя глобально перехватывать навигацию в MVP.

## 11. Рейтинг треков

В актуальном публичном и авторизованном API AzuraCast отсутствует встроенный like/dislike/rating endpoint. Listener Requests не являются рейтингом.

Собственная система рейтинга планируется после MVP:

- WordPress REST endpoint;
- серверное подтверждение текущего трека;
- идентификатор `station + song.id + played_at`;
- like/dislike;
- rate limiting и защита от повторных голосов;
- агрегированное хранение в WordPress;
- экспорт;
- будущий webhook/интеграционный API.

Рейтинг не заявляется как нативная функция AzuraCast и сам по себе не влияет на AutoDJ.

## 12. Proxy и CORS

### 12.1. Политика

- direct browser request является стандартным режимом;
- proxy выключен по умолчанию;
- proxy разрешается только для JSON metadata;
- аудиопоток через WordPress/PHP не проксируется.

### 12.2. Защита proxy

- только сохранённый HTTPS origin AzuraCast;
- запрет loopback, private, link-local и metadata IP;
- ограничение redirects;
- короткий timeout;
- ограничение размера ответа;
- WordPress HTTP API;
- transient cache;
- endpoint не принимает произвольный URL от клиента;
- отсутствие API key во frontend.

## 13. Безопасность и приватность

- прекращение прямого исполнения PHP через `ABSPATH`;
- capability checks;
- nonce для административных действий;
- REST permissions и rate limits;
- sanitization до сохранения;
- context-aware escaping при выводе;
- JSON через `wp_json_encode`;
- отсутствие секретов в DOM, shortcode и экспорте;
- external service disclosure в `readme.txt`;
- текст для Privacy Policy через WordPress API, если используется серверный proxy или рейтинг;
- запросы к AzuraCast раскрывают сервису IP посетителя при browser-side metadata fetch и воспроизведении потока.

## 14. Доступность

Цель — WCAG 2.2 AA:

- нативные `button` и `input[type=range]`;
- доступные имена play/pause и mute/unmute обновляются по состоянию;
- видимый `:focus-visible`;
- управление с клавиатуры;
- статусные сообщения без лишнего речевого шума;
- ошибки через подходящий live region;
- контраст текста и controls;
- touch targets минимум 44×44;
- reduced motion;
- семантический порядок DOM;
- обложка декоративна либо получает корректный alt по контексту;
- autoplay выключен по умолчанию.

## 15. Локализация

- обязательные языки: английский и русский;
- исходные строки рекомендуется хранить на английском;
- text domain: `net-fm-player`;
- JavaScript strings передаются через WordPress i18n/localization API;
- интерфейс поддерживает RTL на уровне logical properties;
- строки AzuraCast не вставляются как доверенный HTML.

## 18. Управление данными и uninstall

- Deactivate не удаляет данные.
- При Delete по умолчанию удаляются plugin options, presets, transients, cache и будущие рейтинги.
- В настройках доступен opt-in «Сохранить данные после удаления плагина».
- Перед удалением пользовательских рейтингов/пресетов в будущих версиях должен быть доступен экспорт.
- Удаление выполняется через безопасный `uninstall.php` или эквивалентный WordPress uninstall hook.

## 19. Критерии готовности версии 1.0

1. Станция подключается по base URL и shortcode.
2. Direct stream работает без AzuraCast metadata.
3. Mount points определяются и отображаются корректно.
4. Metadata error не останавливает аудио.
5. Square и Vinyl завершены для desktop/tablet/mobile.
6. Full, Compact, Mini, Sticky и Floating проходят responsive matrix.
7. Shortcode, Gutenberg и Elementor используют единый renderer.
8. Несколько плееров на странице корректно координируются и уничтожаются.
9. Media Session работает в поддерживаемых браузерах.
10. Все controls доступны с клавиатуры и имеют понятные accessible names.
11. Русский и английский интерфейсы не содержат жёстко заданных непереводимых строк.
12. Настройки безопасно очищаются, а вывод экранируется по контексту.
13. CSS не выходит за `.nfp`.
14. Proxy не может быть использован для произвольных URL или private network access.
15. При удалении данные очищаются согласно выбранной политике.
16. Пройден Plugin Check и ручная WordPress/Elementor матрица.
17. `php -l` успешен для всех PHP-файлов, а `git diff --check` не находит ошибок.
